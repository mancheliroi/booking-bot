# Booking Bot — мультитенантный Telegram-бот для онлайн-записи

Один бот обслуживает сколько угодно компаний: у каждой своя ссылка-приглашение, свои услуги, сотрудники, тексты, расписание и (по желанию) приём онлайн-оплаты. Клиент сам выбирает мастера, услугу, день и свободное время, оставляет телефон — администратор компании сразу получает уведомление.

## Возможности

**Для клиентов**
- заходят по персональной ссылке своей компании `t.me/<бот>?start=<код_компании>`;
- выбор мастера (если их несколько), услуги, дня (выходные скрыты) и только реально свободного времени;
- телефон одной кнопкой «Отправить номер»;
- онлайн-оплата при записи, если компания её включила, с ручной и автоматической проверкой статуса;
- «Мои записи» и отмена своей записи;
- кнопка «Контакты» с адресом и телефоном.

**Для владельца компании — управление без программиста (`/admin`)**
- **услуги и цены**: добавить, изменить название/цену/длительность, скрыть или вернуть;
- **сотрудники**: у каждого своё независимое расписание записей;
- **тексты бота**: приветствие, сообщение после записи, контакты;
- **расписание**: часы работы, шаг слотов, выходные и часовой пояс — свои для каждой компании;
- **оплата**: подключить ЮKassa или Stripe, включить обязательную предоплату;
- **рассылка**: сообщение всем, кто писал боту;
- **статистика**: предстоящие записи, новые за неделю, популярные услуги, выручка;
- `/day 25.10` — записи на дату, уведомления о новых записях/отменах/оплатах.

**Для главного разработчика (`/companies`)**
- создать компанию (имя, код для ссылки, Telegram ID владельца);
- включить/выключить компанию, посмотреть её статистику;
- добавить или убрать админа любой компании. Чтобы самому редактировать услуги
  конкретной компании, супер-админ добавляет себя в её админы и дальше работает
  через обычный `/admin`, как любой владелец бизнеса — отдельная панель для этого не нужна.

**Оплата (ЮKassa / Stripe)**

Публичный вебхук под уведомления о платеже не поднимается — это бы требовало
отдельного домена и SSL-сертификата на каждую компанию. Вместо этого:
- клиент получает ссылку на оплату и кнопку «Я оплатил(а)» для ручной проверки;
- фоновая задача (`app/scheduler.py`) сама раз в 30 секунд опрашивает статус ещё не оплаченных записей;
- если оплата не пришла за `PAYMENT_HOLD_MINUTES`, слот освобождается автоматически.

**Под капотом**
- расчёт слотов учитывает длительность услуги и расписание конкретного мастера: 2-часовая услуга не встанет за час до закрытия и не наложится на чужую запись;
- повторная проверка слота перед сохранением — два клиента не займут одно время;
- время хранится в UTC, показывается в часовом поясе компании.

## Стек

Python 3.12 · aiogram 3 · SQLAlchemy 2 (async) · SQLite / PostgreSQL · httpx (ЮKassa/Stripe) · pydantic-settings · Docker · pytest

## Запуск

```bash
cp .env.example .env    # укажите BOT_TOKEN и ADMIN_IDS (ваш Telegram ID)
docker compose up -d --build
```

Без Docker:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

После запуска откройте бота от своего Telegram ID (из `ADMIN_IDS`) и отправьте
`/companies`, чтобы создать первую компанию и получить её ссылку для клиентов.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

## Структура

```
app/
  main.py            — запуск бота и фоновой задачи оплаты
  config.py          — настройки из .env
  db.py              — модели и инициализация БД
  repo.py            — запросы к базе
  slots.py           — расчёт свободного времени (чистые функции)
  admin_utils.py      — парсинг дат/чисел/расписания, транслит для слага
  ui.py              — клавиатуры и форматирование
  scheduler.py       — фоновая проверка оплаты и просроченных холдов
  payments/
    base.py          — общий интерфейс провайдера
    yookassa.py      — ЮKassa
    stripe_provider.py — Stripe
    registry.py      — выбор провайдера по настройкам компании
  handlers/
    user.py          — сценарий записи для клиента
    company_admin.py — панель владельца компании: /admin
    super_admin.py   — панель главного разработчика: /companies
tests/               — тесты слотов, репозитория и платёжного реестра
```
